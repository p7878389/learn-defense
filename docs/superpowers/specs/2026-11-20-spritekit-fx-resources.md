# SpriteKit 特效资源化方案与 MVP

## 目标和范围

把特效的外观参数、固定节点组合和动作节奏交给 `.sks` 资源维护。常见调色、粒子密度、扩散、淡出和受击动作调整无需修改 Swift 业务逻辑；修改资源后仍需重新打包并验证。

本次 MVP 接入经典战斗的普通命中、墨点退场、存活敌人的受击反应，并导出真实 SpriteKit 动态预览。保留现有素材与角色比例，不引入新依赖，不更换引擎。森林模式、雷霆、冰晶完整迁移、完整特效预算系统留到后续阶段。

平台：iOS 17 / macOS 14；Swift Package `LearnKit`；SwiftUI + SpriteKit。

## 现状与优先级

| 内容 | 当前维护方式 | 目标 | 本次 |
| --- | --- | --- | --- |
| 墨点退场 | `Effects.swift` 每颗形状节点 + 动作 | `InkBurst.sks` 粒子参数 | 接入，保留原调用参数 |
| 普通命中 | `ShotAttack.splat` 静态命中贴图 + 等待淡出 | `PeaImpact.sks` 组合节点与时间线 | 接入普通圆弹；其他弹种保持原行为 |
| 受击 | 闪白，缺少本体反应 | `CombatActions.sks` 保存命名动作 | 增加存活精灵的短后仰回正；保留冰冻染色语义 |
| 冰晶 | 代码粒子与烘焙帧 | 粒子 `.sks` + 已有帧素材 | 后续 |
| 雷霆 | 按场景时间推进的定制演出 | 聚云、单束雷、落点分别资源化 | 后续，保留动态目标调度 |

昨晚修复的子弹可见时间 0.35–0.8 秒、回合休息保留退场动画，不再调整。

## 资源职责

1. **粒子 `.sks`**：数量基准、出生率、寿命、速度、方向范围、重力、旋转、颜色与透明度/缩放曲线。
2. **组合 `.sks`**：根节点 `effect`，其下放接触光、冲击环、粒子；使用相对坐标、稳定节点名。User Data 的 `action` 字段引用动作库中的名字。
3. **动作 `.sks`**：`CombatActions.sks` 是原生 SpriteKit Action 库，保存 HitReaction、ImpactFlash、ImpactRing、ImpactLifetime，通过公开 `SKAction(named:from:)` 加载。实测 Xcode 保存场景时会清除运行时动作键，因此不依赖场景中的 `action(forKey: "play")`；布局与动作分别编辑，由加载器按稳定名字绑定。
4. **纹理**：透明小纹理与资源同目录。节点 `userData.texture` 指定文件名，运行时统一从 `Bundle.module` 解析，避免依赖主 App 包查找；编辑器预览和运行时加载均需验证。
5. **运行时绑定**：坐标、调用方颜色、整体比例、动态粒子数量、伤害结算、暂停与清理。配置值只有一个来源，运行时不重复写资源中的粒子参数。

MVP 用三个固定资源标识，不先增加通用 JSON 配方语言。待出现第二套可选择的弹种资源时，再增加“弹种/皮肤 → 资源名”的映射表。

## 文件与资源结构

```text
Sources/LearnGame/
  Game/FXLibrary.swift          # 加载、验证、缓存、复制、纹理绑定及生命周期
  Resources/Effects/
    InkBurst.sks               # 单次有限粒子发射器
    PeaImpact.sks              # 接触光 + 椭圆冲击环 + 碎屑
    CombatActions.sks          # 原生命名动作库，含受击与命中时间线
    InkDrop.png / ImpactRing.png / ImpactFlash.png
    README.md                  # 编辑步骤、节点约定、来源、验收方法
Tests/LearnGameTests/
  FXResourceTests.swift        # 真正加载包资源并驱动 SpriteKit
```

`.sks` 是交付和后续编辑的源文件，不在构建时由 Swift 重新生成覆盖。纹理为本次用几何绘制制作的透明素材，无外部授权依赖。正式制作可替换纹理，保持节点约定。

## MVP 画面设计

- **普通命中**：接触处短促亮核，随后一圈非满屏的绿色冲击环向外扩散；少量碎点沿受力方向散开。主体在约半秒内收束，不盖住题目牌。
- **墨点退场**：使用有透明边缘的墨滴纹理，大小和飞出速度有变化，带轻微下坠；颜色仍由当前敌人/道具传入。保留调用方 `count`、`scale` 的效果。
- **受击**：只在存活角色的视觉精灵上播放轻后仰再回正，短时间内完成。重复命中替换同名动作，不累计旋转；不移动敌人逻辑坐标，不冻结场景。
- **比较方法**：正常速度与慢放观看实际引擎导出；另提供关键帧，区分形态、时间线、颜色绑定与清理结果。预览不使用网页模拟或概念图冒充引擎效果。

## 加载与生命周期

- `Bundle.module` 显式定位资源；模板不加入场景，每次深复制后独立播放。
- 只解档随 App 打包的可信资源；资源缺失、类型错误、缺少必要节点或动作时记录诊断信息，特效失败不影响伤害回调。
- 所有贴图在加载时绑定，并共享纹理对象。效果模板仅首次读取。
- 组合效果的结束由根节点动作决定；粒子效果的清理时间从实际 `numParticlesToEmit / particleBirthRate + particleLifetime + particleLifetimeRange / 2` 推导，不另写一份视觉时长。
- 发射器保持有限发射；不使用 `targetNode`，不在帧更新中改父节点。
- 实测单独修改场景 `speed` 不足以冻结所有粒子；暂停入口同步资源根节点 `isPaused`，新增节点同样继承暂停。效果被移除或场景销毁后不保留完成回调。验证连续触发和暂停恢复后可以清空。
- 受击的动作只使用绝对旋转回到零，不覆盖角色朝向、行走帧、锚点和冰冻染色。

## 业务兼容

- 不修改 `GameScene.fire` 的伤害、命中次数、最终一发判定、击杀奖励、能量和目标选择。
- 普通弹接入资源后仍保留 `impactSplat` 顶层节点名，兼容已有行为测试。
- 冰弹继续使用原路径；非普通圆弹的原命中素材继续可用。
- `InkBurstEffect(color:scale:count:)` 与 `DefeatEffect.makeEffect` 接口不变；现有掉防具、地雷、植物破坏也会使用新墨点资源。
- `EnemyNode.flash` 保留闪白与冻色恢复，只给未 doomed 的精灵增加资源动作。

## 风险与验证

| 风险 | 验证 |
| --- | --- |
| Swift Package 内资源能找到，嵌套纹理却找不到 | 实际解档、检查纹理像素，Metal 真实渲染输出 |
| 归档在 macOS 生成，iOS 无法读取 | iOS 模拟器构建与运行验证（有可用运行时才执行）；明确报告未覆盖的平台 |
| 模板复制共享可变状态 | 同时播放两个不同颜色/数量实例，分别清理 |
| 暂停后粒子继续喷或节点提前清除 | scene.speed = 0 跨多个渲染帧后检查画面和节点，恢复后验证清空 |
| 动画改动影响结算或冰冻 | 连发顺序、一次答对一伤害、只结算一次、冻色恢复及已有战斗回归 |
| `.sks` 看似有效却无法编辑 | 用 Xcode 打开实际资源检查粒子/场景编辑器；未验证时不声称可视化编辑已通过 |

GitNexus 预分析：`InkBurstEffect` 为 CRITICAL（协议动态分派及多流程复用），`flash` 为 HIGH（答题和爆炸链路），`splat` 为 UNKNOWN（静态调用未入图）；已通过源码查明 `ShotAttack.perform` 的调用。风险以集成和回归测试覆盖，不以空图结论豁免。

## 后续落地顺序

1. 本次三种资源完成加载、编辑、预览、清理的闭环。
2. 扩展星弹、爱心、花瓣的命中/尾迹映射；接入资源选择配置，减少弹种分支。
3. 迁移其余四类退场与冰晶发射器；保留各自视觉差异。
4. 将雷霆拆成可复用的单次资源；动态落雷位置与场景时钟继续由调度器负责。
5. 取得真机节点数、绘制次数、帧耗时基线后，再决定统一预算与降级档位；不把 `.sks` 格式本身当作性能提升证据。

## 验收标准

- 编辑 `.sks` 的扩散、寿命、动作时长，以及不由调用方覆盖的粒子数量/颜色，可在无业务代码修改的情况下改变运行结果；墨点的动态 count/color/scale 继续沿用原接口。
- 三个资源都由游戏真实调用；没有生产环境运行时绘图替代资源加载。
- 两个同时播放的实例互不污染，暂停恢复正常，有限时间后无特效节点残留。
- 普通攻击、连发、冰冻、死亡和回合休息行为通过回归测试。
- 提供实际引擎动态预览、关键帧和准确的测试记录，区分实测与未覆盖项。
