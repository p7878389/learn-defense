# 存储可靠性与资源加载优化实施计划

**目标：** 落实本次代码分析中的七项建议，先保证数据可靠性，再减少已确认的重复工作；性能改造以测量结果为依据。

**架构：** 复用现有 SwiftData 模型和成长规则，不增加表或依赖。持久化成功后才发布内存状态；结算、题库替换使用明确的事务边界。头像加载与完整动画缓存分离。

**技术：** Swift、SwiftData、SwiftUI、SpriteKit、Swift Testing。

**需求来源：** 本会话已确认的优化排序及用户“按推荐方案执行”。使用当前本地 main 的 a06bd36 为基线。

## 约束与验收重点

- 不改变奖励数值、购买条件、未结算退出语义、战斗伤害与命中顺序。
- 不增加数据库表、资源格式或外部依赖；保留旧存档兼容性。
- 读取失败不能覆盖原成长资产；保存失败不能发布成功状态，必须允许重试。
- 重复结算不能重复发奖；奖励、对局、答题明细必须一致。
- 题库替换失败必须保留旧文件指纹与索引，下次可重新导入。
- 头像像素/裁切与动画首帧一致；查看头像不预热完整动画。
- 自动存档仍保持最多回退两秒，关键操作仍保存。

## 实施结果与测量

已实现前五项：损坏成长档案写保护与重读入口；经典奖励、对局和答题明细原子提交及结算重试；题库文件记录和索引原子替换；头像首帧加载；未变化配置跳过写库。存储错误改为向调用方抛出，项目内调用点已适配。数据库模型和奖励规则保持兼容。

验证：完整 Swift 测试 430 个通过（LearnGame 225、LearnCore 205）；iOS Simulator Debug 构建通过；Git diff --check 通过。新增回归覆盖只读数据库失败、原档案保护、修复后重试、跨孩子隔离、重复结算、题库中断回滚、配置变更及头像像素一致性。

Release 测量命令：

```sh
LEARN_OPTIMIZATION_PROFILE=1 DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test -c release --filter OptimizationMeasurements
```

环境为当前 Apple Silicon Mac。固定森林第六关场景推进 2000 个 50ms 模拟步，保存 50 次；写入真实临时 SQLite 存储。

| 项目 | 样本 | 平均 | P95 | 最大 |
| --- | ---: | ---: | ---: | ---: |
| 50ms 模拟步进 | 2000 | <0.001ms | 0.001ms | 0.009ms |
| 渲染状态同步 CPU 调用 | 2000 | 0.063ms | 0.029ms | 101.143ms |
| 冒险存档写盘 | 50 | 0.606ms | 0.814ms | 1.106ms |

第六、七项的执行结论：暂不引入异步存储线程或额外的战斗索引结构，保留两秒存档间隔、关键操作保存和现有确定性战斗算法。当前桌面样本中，存档和模拟循环未显示出足以支撑这些改造的耗时。

限制：测量不包含 iPad 实机 GPU 帧时间和完整屏幕合成；渲染有首次加载的较大峰值，仍需在目标 iPad 上用 Instruments 定位，不能将桌面结果作为实机帧率保证。头像加载以实际缓存帧数回归验证：普通僵尸头像不再将 22 帧动画加入缓存，只解码所需首帧。

收尾：未自动提交、合并或删除 worktree；主检出的 main 保持原状。
