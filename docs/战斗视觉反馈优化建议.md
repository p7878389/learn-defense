# 战斗视觉反馈优化建议

日期：2026-11-06  
状态：建议稿，尚未实施；基于源码分析，未进行游戏运行与实机视觉验证。

## 1. 目标与问题

- 子弹飞行太快，难以看清弹体，子弹皮肤缺少展示机会。
- 多株豌豆射手种下后，只有最前面的植物发射，后排缺乏参与感。
- 大招能量积累、就绪和释放之间缺少连续、明确的视觉反馈。
- 击杀僵尸的表现不明显，普通受击与死亡难以快速区分。

优先解决“弹道可辨识”和“同路多株协同攻击”，再强化击杀与大招。以下数值均为首轮调试建议，需要实机确认。

## 2. 已确认的当前实现

| 项目 | 源码事实 | 位置 |
| --- | --- | --- |
| 子弹飞行 | 飞行时间限制在 0.15～0.45 秒，没有拖尾 | `Packages/LearnKit/Sources/LearnGame/Game/AttackStrategy.swift`，`ShotAttack.perform` |
| 发射者选择 | 每次只选择目标同路最靠右的一株植物 | `Packages/LearnKit/Sources/LearnGame/Game/GameScene.swift`，`fire` |

| 大招能量 | 分段圆点显示能量，就绪后按钮呼吸缩放 | `Packages/LearnKit/Sources/LearnGame/Views/GameView.swift`，`UltimateButton` |

## 3. 子弹弹道与皮肤

组合调整飞行时间、尺寸、枪口和命中反馈，避免仅靠减速解决问题。

| 项目 | 建议 |
| --- | --- |
| 飞行时间 | 中远距离约 0.4～0.7 秒，近距离约 0.2～0.3 秒，保留距离差异 |
| 弹体大小 | 在当前基础上放大约 20%～35%，优先保证轮廓清晰 |
| 发射提示 | 枪口出现 0.08～0.12 秒的小光圈或叶片气流 |
| 飞行表现 | 增加长度约 1～2 个弹体的短拖尾，避免长光带盖住皮肤 |
| 命中反馈 | 落点出现同色小爆点，与敌人受击动作同步 |

皮肤贯穿“弹体 → 拖尾 → 命中”三个环节：

- 普通豌豆：干净利落的弹体和短尾迹。
- 冰弹：细小冰晶尾迹，命中时散出冰屑。
- 星弹：轻微旋转，留下少量星点。
- 花瓣弹：轻摆，命中时散出花瓣。

减速后需检查连续答题场景，避免上一轮子弹尚未到达，目标已消失或后续攻击出现重复结算。优先保持答题响应速度，不把每次输入强制阻塞到动画结束。

## 4. 多株植物协同攻击

推荐每次答对后，目标所在路的多株植物共同参与攻击，相邻植物错开 0.06～0.1 秒起射，形成短促、有层次的齐射。

### 规则边界

**一次答对仍只扣一次血；整轮齐射只结算一次击杀和奖励。**

当前血量与答题数量关联，直接按植物数量叠加伤害会改变难度。视觉参与与伤害结算需要分开处理。

### 表现建议

- 每株植物都有枪口反馈，展示各自的子弹皮肤。
- 多颗子弹略微错开轨迹，避免完全重叠。
- 限制整轮齐射的总时长，避免植物越多等待越久。
- 普通命中反馈可多次播放，死亡、奖励与业务回调只能触发一次。
- 冰冻、击退等特殊能力首版保持现有规则，不因齐射自动叠加。
- 多种植物是否增加额外战术收益，作为独立玩法需求讨论。

## 5. 大招能量与释放

### 能量积累与就绪

保留适合当前界面空间的分段能量设计，强化状态变化：

- 获得能量：新增一格弹亮一次，约 0.25 秒；仅在实际增加能量时播放。
- 即将充满：末段更明亮，提示接近就绪。
- 充满瞬间：一次环形光波和简短提示音，随后转为柔和呼吸光。
- 就绪状态：常驻清晰的“已就绪”文字，不仅依赖颜色传达。

### 释放演出

建议总时长约 0.9～1.3 秒，分三拍：

| 阶段 | 表现 |
| --- | --- |
| 蓄力 | 约 0.2 秒，植物或场景中心聚光 |
| 爆发 | 冲击波扫过战场，命中位置依次响应 |
| 收尾 | 敌人退场、残留粒子消散，能量条归零 |

清场大招建议使用低透明度色光与有方向的冲击波，降低强白色全屏遮罩对下层表现的遮挡。视觉归零动画应跟随真实能量状态，不能额外改变能量消耗规则。

当前大招需首次答对挑战题才释放，因此“可用提示”“进入挑战”和“成功释放”必须区分，不能点击按钮就播放成功爆发。

## 6. 命中与击杀反馈

优先强化敌人本体动作，再补充粒子。推荐节奏：

**命中亮一下 → 短暂后仰 → 倒下或化散 → 粒子收尾。**

- 普通受击：局部闪亮、轻微后仰，短而清晰。
- 普通击杀：约 0.45～0.65 秒的退场动作，加一圈扩散环与少量碎片。
- 大招击杀：沿冲击波方向分批触发，避免所有效果同时叠成一团。
- 音效：普通命中轻、击杀更明确、大招更饱满；音量让位于题目朗读。
- 单词卡：与击杀效果错开位置，避免遮挡敌人退场。

不建议每次击杀都震屏或增加大号飘字，以免干扰答题。普通战斗靠局部动作表达，大招再使用更强的场景反馈。

## 7. 实施顺序

| 优先级 | 内容 | 目的 |
| --- | --- | --- |
| 第一优先级 | 弹速、弹体尺寸、枪口提示、同路多株齐射 | 看清弹道与皮肤，明确后排植物参与攻击 |
| 第二优先级 | 命中与死亡分层反馈、皮肤专属拖尾和爆点 | 明确打中与击杀，增强皮肤辨识度 |
| 第三优先级 | 能量积累动画、大招蓄力与冲击波演出 | 建立积累、就绪、释放的连续反馈 |

## 8. 验收标准

- 近、中、远距离下均能辨认主要弹体形状，皮肤不会被拖尾遮盖。
- 同路种下多株植物后，能明确看见后排参与攻击。
- 不同数量植物齐射时，一次答对的伤害、奖励及击杀回调均不重复。
- 快速连续答题、目标提前死亡、暂停与恢复时，弹道和结算保持一致。
- 普通受击与死亡在视觉上可清楚区分，退场过程不被单词卡遮挡。
- 能量增加和充满均有明确反馈；进入大招挑战不误播成功释放效果。
- 大招演出有清楚的蓄力、爆发和收尾，同时仍能看清战场。
- 多植物、多敌人及大招同时出现时检查帧率与特效清理，避免节点持续堆积。
- 音效不盖过题目朗读，视觉反馈不妨碍继续答题。
