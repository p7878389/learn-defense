# 字灵守卫 · 成长系统设计方案

> 第一阶段已按本方案实现（分支 `feature/growth-system`），第 10 节的待定项都按默认值执行。与方案的出入：
> - 紫晶弹用新增的宝石形状（`gem`），不是「orb 换紫色」：普通豌豆子弹有现成贴图，换颜色看不出来。
> - 老档案补发时，已满足条件的徽章直接点亮，但不再额外送徽章积分，免得一次拿太多。
> - 买下外观后自动装备，随时可以换回原版。
> - 界面以 [ui-growth/](ui-growth/README.md) 的设计稿为准；主页「今日小目标」、连续打卡、等级称号第一阶段不做。

基于 master `886a3af` 的现有结构。目标：给每个孩子档案加上 **等级（经验）**、**积分**、**徽章**；等级解锁、积分购买 **外观类内容**（子弹、僵尸退场、命中、种植特效、道具皮肤），后期再加会影响玩法的解锁道具。

---

## 1. 现状要点（决定方案怎么接）

- 档案 `Profile` 存在 `profiles.json`；学习记录 `ProgressStore` 每个孩子一个文件 `progress/<id>.json`，由 `AppModel.progress(for:)` 缓存。
- 一局的结算点只有一个：`GameSession.finish(won:)`（通关或失败）；中途退出走 `end()`。
- 外观/特效已经是「LearnCore 纯数据配置 → LearnGame 策略工厂」：
  - 子弹：`DefenderKind.projectile: ProjectileLook` → `ShotAttack/BeamAttack` 里 `UnitSprites.projectile(look) ?? ProjectileArt.make(look)`
  - 僵尸退场：`EnemyLook.defeat: DefeatEffect` → `makeEffect()` → `VisualEffect`
  - 道具：`ItemKind`（icon/name/effects）→ `ItemCommand`
- 游戏页布局（战场铺满、卡牌栏/HUD 叠在篱笆上、道具大招在左侧、答题区只增不减）**本方案不在对局画面里加任何新 UI**，只改特效表现。

## 2. 数据模型与持久化

新增 `LearnCore/Progress/Growth*.swift`：

```swift
/// 一个孩子的成长档案，单独存成 growth/<档案id>.json
public struct GrowthState: Codable {
    var version = 1
    var xp = 0                         // 累计经验，等级由它算出，不单独存
    var coins = 0                      // 当前积分
    var badges: [String: Date] = [:]   // 已获得徽章 id → 获得时间
    var owned: Set<String> = []        // 已拥有的外观 id（买的 + 等级送的）
    var equipped: [CosmeticSlot: String] = [:]  // 每个槽位装备的外观
    var stats = GrowthStats()          // 徽章用的累计数据
}
public struct GrowthStats: Codable {
    var gamesPlayed, gamesWon, threeStarGames, perfectGames: Int
    var firstTryCorrect, bossesDefeated, enemiesDefeated: Int
    var itemsUsed, ultimatesCast: Int
    var wonByDifficulty: [Difficulty: Int]
    var playSeconds, questionsAnswered: Int   // 用来校准单局题量/时长
    var day: String?, gamesToday: Int, wonToday: Bool  // 每日首胜、当天第几局
}
```

- **单独文件 `growth/<id>.json`**，不改 `profiles.json` 和 `progress/*.json` 的结构 → 老存档原样可读。
- 所有字段用 `decodeIfPresent` 带默认值解码，以后加字段不会让旧文件读失败；文件损坏时保留原文件为 `.bak` 再从默认值开始（不覆盖丢数据）。
- **老档案迁移**：第一次没有 growth 文件时，按已有学习记录里的累计答对次数补发经验（每次答对 5 经验，最多补到 Lv.10）和积分（每次答对 1 分），并据此补发等级奖励和免费外观；只做一次，迁移后写文件。
- 删除档案时一并删除 `growth/<id>.json`（`AppModel.delete`）。
- `GrowthStore`（与 `ProgressStore` 同风格，url 为 nil 时只在内存，便于测试），`AppModel.growth(for:)` 缓存。

## 3. 单局题量控制（新增，第一阶段一起做）

**现状问题**：一局出多少题由「怪物只数」决定，而铁桶僵尸要答 2 题、铁门首领要答 3 题，数量随机，所以同一档题量会飘：

| 现状 | 怪物 | 实际题数（不含大招题） |
|---|---|---|
| 幼儿园 入门/标准/挑战 | 6 / 8 / 10 | 6 / 8 / 10 |
| 小学 入门 | 8 | 8（偏短） |
| 小学 标准 | 10 | 期望约 13，随机 12~19 |
| 小学 挑战 | 12 | 期望约 16，随机 14~23（偏长） |

且小学 1~6 年级完全一样，一年级和六年级的专注时长差别很大。

**改法**：按「年级段 × 难度」给一个固定的**题量预算**，出怪计划按题量凑（怪物血量之和 = 题量），不再按怪物只数：

| 年级段 | 入门 | 标准 | 挑战 | 预计时长（含布阵） |
|---|---|---|---|---|
| 中班 | 6 | 7 | 8 | 约 2~3 分钟 |
| 大班 | 8 | 9 | 10 | 约 3 分钟 |
| 一、二年级 | 10 | 12 | 14 | 约 3~4 分钟 |
| 三、四年级 | 12 | 14 | 16 | 约 4~5 分钟 |
| 五、六年级 | 14 | 16 | 18 | 约 4~6 分钟 |

- 难度主要体现在速度、选项数、干扰项，题量只在同年级段里差 ±2~4 题，**最多 18 题**，避免高年级挑战一局拖太久。
- 凑题量时如果剩下的预算放不下 2 血/3 血的怪，就补普通僵尸；首领算在预算里。这样每局题量**固定可预期**，单元测试逐档检查。
- 大招题是孩子主动触发的额外题（每局 0~2 道），不计入预算。
- **错题复习局**：错题少时题目会来回重复，题量改为 `错题数 × 2`，最少 6 题、最多不超过本档题量。
- 时长是按每题 10~15 秒（读题、作答、动画）估的，真机上不一定准。结算时把**本局用时和题数**记进成长统计，试玩一段时间后按实际数据再调这张表（集中在一处配置）。

### 3.1 题量、局数等节奏参数做成配置文件

单局题量、复习局题量、每天全额奖励的局数、每日首胜奖励、经验/积分公式系数、等级曲线参数，全部放进一个配置文件，**代码里不写死数字**：

- 文件：`Packages/LearnKit/Sources/LearnCore/Resources/Config/pacing.json`，跟题库一样随 App 打包。
- LearnCore 里对应 `PacingConfig: Codable`。读取顺序：内置 JSON → 代码里的默认值兜底（JSON 缺字段或写错时用默认值，并在主页「题库问题」区提示哪一项无效，不崩溃）。
- 年级段用列表配置，以后加「七年级」或拆分年级段只改 JSON；每个难度一个题量，新增难度也只加一项。
- 加载后先校验：题量 1~40、倍率大于 0、曲线递增等。不合法的项用默认值。

```json
{

    { "grades": ["k3"],       "easy": 8,  "normal": 9,  "hard": 10 },
    { "grades": ["g1", "g2"], "easy": 10, "normal": 12, "hard": 14 },
    { "grades": ["g3", "g4"], "easy": 12, "normal": 14, "hard": 16 },
```

- 徽章和外观清单（解锁等级、价格）也按同样方式放进 `badges.json`、`cosmetics.json`。以后加徽章、调价格、调解锁等级都只改 JSON；只有新增一种特效的画法才需要写代码。
- 测试直接读打包的 JSON，跑第 3、4 节的题量检查和升级节奏模拟，确保改配置后节奏仍在目标范围内。
- 后续可选：在「编辑档案」里给家长加「每局题量 少/标准/多」「每天全额奖励局数」两项，覆盖档案自己的值。第一阶段先不做界面，数据结构先预留。

## 4. 经验与等级

**设计目标（按每天 2~3 局、每周约 12 局估算）**：

| 节点 | 大约局数 | 大约时间 |
|---|---|---|
| Lv.2 | 第 1 局 | 第一天（马上有正反馈） |
| Lv.5 | 8~10 局 | 第一周 |
| Lv.10 | 约 40 局 | 一个月 |
| Lv.15 | 约 100 局 | 两个月 |
| Lv.20 | 约 175 局 | 一学期 |
| Lv.30 | 约 325 局 | 半年多 |

前期一两局升一级，之后**任何一级都不超过约 15 局（一周多一点）**，不会出现「好久升不了级」的断档；两次升级之间还有徽章和积分购物作为短期目标。

**每局经验先做归一化**：题量随年级不同，如果按题数给经验，高年级升级会快很多。所以答题经验按**首答正确率**算，不按题数：

| 项目 | 经验 |
|---|---|
| 答题 | 首答正确率 × 60（全对 60，答对一半 30） |
| 通关奖励 | 20（失败没有） |
| 星级 | 每颗星 +10（失败没有） |
| 难度倍率（乘在总和上） | 入门 ×1.0 · 标准 ×1.2 · 挑战 ×1.5 |
| 每日首胜 | +30（每天第一次通关，鼓励每天来、不鼓励一次玩很久） |
| 当天第 6 局起 | 本局经验减半，结算页提示「今天很努力了，休息一下眼睛吧」 |

典型一局：标准难度、正确率 85%、2 星 = (51+20+20)×1.2 ≈ **109**；入门全对 3 星 = (60+20+30)×1.0 = **110**；挑战全对 3 星 = (60+20+30)×1.5 = **165**；失败、正确率 60% = 36×倍率。所以每局约 100 经验，挑战难度多 50%，值得挑战，但不至于只刷挑战。

**等级曲线**：Lv.L 升到 L+1 需要 `min(100×L − 40, 1500)` 经验：
- 每级需要：1→2 是 60、2→3 是 160、3→4 是 260……14→15 是 1360，15→16 是 1460，16 级起每级固定 1500。
- 累计到达：Lv2 要 60，Lv5 要 840，Lv10 要 4,140，Lv15 要 9,940，Lv20 要 17,400，Lv30 要 32,400。
- **不设等级上限**：30 级以后外观已经全部解锁，继续升级仍然送积分，用来买还没买的外观。

**用测试把节奏固定下来**：模拟「典型一局 100 经验」连续玩，断言第 1 局升 Lv.2、8~10 局到 Lv.5、35~45 局到 Lv.10、任意一级不超过 16 局。以后调参数时，节奏一旦跑偏测试就会失败。

## 5. 积分

**来源**

| 来源 | 积分 |
|---|---|
| 答题 | 首答正确率 × 20 |
| 通关 | 入门 10 · 标准 15 · 挑战 25 |
| 星级 | 每颗星 +5 |
| 每日首胜 | +10 |
| 升级 | 每升 1 级 +30 |
| 获得徽章 | 每枚 +20 ~ +100（见徽章表） |

当天第 6 局起和经验一样减半。一局通常 30~50 积分，加上升级和徽章，普通外观 3~5 局能买一件，稀有外观 8~10 局。

**消耗**：只用于在「收藏馆」购买外观（第三阶段起也可买可携带道具）。积分不能被扣成负数，购买失败不扣分；没有任何真钱入口。

## 7. 可解锁 / 可购买内容

每件外观：`CosmeticKind { id, name, icon, slot, unlockLevel, price, payload }`
- 等级 < `unlockLevel`：🔒「Lv.N 解锁」
- 达到等级、`price == 0`：**自动送**（升级时提示「解锁了 xx」）
- 达到等级、`price > 0`：可用积分购买
- 每个槽位都有一个「原版」默认项，随时可换回

| 槽位 | 外观 | 解锁等级 | 价格 | 实现 |
|---|---|---|---|---|
| **子弹** | 原版 | 1 | 送 | 不替换 |
| | 金星弹 | 3 | 送 | 星星形、金色（已有 `star`） |
| | 花瓣弹 | 5 | 100 | 已有 `petal`，珊瑚色 |
| | 紫晶弹 | 7 | 150 | `orb` 换紫色 |
| | 爱心弹 | 10 | 250 | 新增 `heart` 形状 |
| **僵尸退场** | 原版（各僵尸自带） | 1 | 送 | 不替换 |
| | 星星飞散 | 2 | 送 | 已有 `sparkle` |
| | 涟漪 | 4 | 80 | 已有 `ripple` |
| | 彩纸礼花 | 6 | 150 | 新增 `confetti` |
| | 烟花 | 12 | 300 | 新增 `firework` |
| **道具皮肤** | 冰冻符 → 🧊 冰块符 | 4 | 60 | 只换图标/名字，效果不变 |
| | 爱心叶 → 💝 礼物心 | 6 | 60 | 同上 |
| | 幸运星 → 🌟 闪耀星 | 8 | 60 | 同上 |
| **命中特效**（二期） | 无 / 火花 / 小星星 / 爱心泡泡 | 3 / 8 / 14 | 送 / 120 / 200 | 新 `VisualEffect`，子弹命中点播放 |
| **种植特效**（二期） | 原版 / 落叶飞散 / 金光圈 | 5 / 9 | 送 / 150 | 新 `VisualEffect` |
| **大招特效**（二期） | 原版 / 彩虹闪 / 星雨 | 11 / 15 | 200 / 300 | 替换 `ScreenFlashEffect` |
| **解锁道具**（三期，影响玩法） | ☀️ 太阳花瓣（+75 阳光）Lv.6 解锁进掉落池；🛡 护盾叶（下一只到家的僵尸不扣血）Lv.10；开局携带 1 个道具 Lv.8 | — | — | 新 `ItemEffect` + `ItemCommand` |

子弹皮肤只替换**普通豌豆类（`orb`）子弹**，寒冰射手的冰豌豆、杨桃的星星保留原样，避免孩子分不清哪个会减速。

**怎么接入（不在场景里写分支）**：LearnCore 新增纯数据 `Loadout`：

```swift
public struct Loadout: Sendable {
    var projectile: ProjectileLook?          // 替换 orb 子弹
    var defeat: DefeatEffect?                // 替换所有僵尸退场
    var hit: HitVisual?                      // 二期
    var plant: PlantVisual?                  // 二期
    var itemSkins: [String: ItemSkin]        // 道具 id → 图标/名字
    func projectile(for kind: DefenderKind) -> ProjectileLook
    func defeat(for kind: EnemyKind) -> DefeatEffect
    func skin(_ item: ItemKind) -> ItemKind
    static let standard = Loadout()          // 原版
}
```

`GrowthState.equipped` + `CosmeticCatalog` → `Loadout`（未知/未拥有的 id 一律忽略，回退原版）。`GameSession` 开局把 `Loadout` 交给 `GameScene`；`DefenderNode` / `EnemyNode.defeat()` / 掉落道具只调用 `loadout.projectile(for:)`、`loadout.defeat(for:)`、`loadout.skin(_:)`，再走原有 `makeEffect()` 等工厂。新增外观 = 往 `CosmeticCatalog` 加一条，新增特效类型 = 给枚举加 case + 实现 `VisualEffect`，和现有扩展方式一致。

## 8. 界面

- **档案主页**（`ProfileHomeView` 顶部名字那一行）：等级牌「Lv.5」+ 经验进度条（`230/300`）+ 🪙 积分；右侧加「收藏馆」「徽章」两个按钮（和「编辑档案」并列）。主页是 ScrollView，不影响游戏页。
- **结算页**（`ResultView`）：统计行下面加一条奖励条「⭐ 经验 +194 · 🪙 积分 +34」+ 经验条动画；升级时显示「升到 Lv.3！解锁：金星弹」；新徽章用小徽章片展示。弹窗内容变高时整体放进 ScrollView、「记一记」区降低最大高度，保证 11 寸横屏放得下按钮。
- **收藏馆**（新 sheet `CollectionView`）：顶部显示等级和积分；按槽位分段（子弹 / 僵尸退场 / 道具皮肤，二期加命中、种植、大招）；卡片显示预览图标、名字、状态按钮：🔒 Lv.N 解锁 / 🪙 价格「购买」/「装备」/「使用中」。购买前弹确认，积分不够时按钮置灰并提示还差多少。
- **徽章墙**（新 sheet `BadgeWallView`）：网格，已得彩色 + 获得日期，未得灰色 + 条件文字和进度（如「首答正确 63/100」）。
- **对局画面不加新 UI**，只在特效上体现装备的外观。

## 9. 分阶段

**第一阶段（本次实现）**
1. LearnCore：**节奏配置 `PacingConfig` + `pacing.json` / `badges.json` / `cosmetics.json`**（读取、校验、默认值兜底）；**单局题量预算**（`GameTuning` 按年级段 × 难度给题量，`WavePlan` 按题量凑怪，错题复习局按错题数定题量）；`GrowthState/Stats`、`LevelCurve`、`GrowthRules`（经验/积分结算、每日首胜、当天第 6 局起减半）、`BadgeCatalog` + 判定、`CosmeticCatalog`（子弹 5 + 退场 5 + 道具皮肤 3）、购买/装备/自动解锁、`Loadout`、`GrowthStore` + 老档迁移。
2. LearnGame：`GameSession` 统计本局数据（首答对、改对、星级、首领、道具、大招）并在 `finish` 结算；`AppModel.growth(for:)`、删除档案时清理；`Loadout` 接入子弹、退场、道具图标；新增 `heart` 子弹形状、`confetti`/`firework` 退场特效。
3. 界面：主页等级/积分 + 收藏馆 + 徽章墙；结算页奖励条、升级/解锁/新徽章。
