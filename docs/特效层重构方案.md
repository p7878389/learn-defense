# 特效层重构方案（SpriteKit 内重构）

日期：2026-11-19
状态：方案稿，尚未实施；基于源码阅读与 GitNexus 影响分析，未做真机性能测量。
范围：经典模式战斗场景（`Packages/LearnKit/Sources/LearnGame/Game/`，含庭院、林间草坪两张地图）。
关联：[战斗视觉反馈优化建议](战斗视觉反馈优化建议.md)（表现层"做什么"）；本文解决"用什么方式、什么结构做"。

不在范围内：

- **森林地图**：`Views/ForestDefenseView.swift`、`Views/ForestCombatViews.swift`、`LearnCore/Game/ForestDefense.swift` 等森林地图代码，以及它专用的 `Resources/Sprites/Maps/forest-*` 素材（含 `forest-fx-*.png`），本方案不修改、不复用。
- SwiftUI 界面层动画。

## 1. 结论与原则

继续使用 SpriteKit，不换引擎、不为战斗特效引入第三方依赖。重构目标是让特效**更好看、更省、更好调**：

- **按类型分工实现**：粒子用 `.sks` 粒子文件，标志性大特效用序列帧，材质效果用着色器，动作手感用 `SKAction`（详见第 3.1 节）。代码只决定"何时、何处播放"，外观尽量交给编辑器和素材。
- **纹理化**：一次性粒子不再用 `SKShapeNode`，改为贴图驱动的 `SKEmitterNode` / `SKSpriteNode`，可合批、可加法混合发光。
- **统一出口**：所有战斗特效经同一个特效层播放，统一层级、预算、降级与清理。

不变的边界：

- 不改伤害、击杀、奖励、能量等规则与回调时序（`GameScene.fire` 的结算逻辑本方案不动，齐射另立需求）。
- 不改 `LearnCore` 的 `DefeatEffect` 枚举原始值（`cosmetics.json` 依赖 `inkBurst/ripple/sparkle/confetti/firework`）。
- 保留 `VisualEffect` 协议与 `DefeatEffect.makeEffect(color:scale:count:)` 签名，调用方无感。
- 保留测试依赖的节点名：`skinMuzzleFlash`、`iceTrail`、`ultimateThunder`、`thunderSpark`、`thunderShade` 等。

## 2. 现状（源码事实）

### 2.1 当前实现方式

| 方式 | 用在哪里 | 问题 |
| --- | --- | --- |
| 纯代码形状（`SKShapeNode` + `SKAction`） | 五种退场效果（墨点、涟漪、星星、彩纸、烟花）、皮肤枪口光、首领横幅底板 | 观感偏平；不能合批；烟花用了开销大的 `glowWidth`；调参要改代码重编译 |
| 代码运行时烘焙贴图（CGContext） | 冰晶光环与冰爆 20 帧（`IceCombatEffects`）、雷霆星屑（`ThunderStrikeEffect.sparkTextures`） | 比形状节点好，但外观全靠代码调，美术难以介入 |
| 图片素材 | 雷霆大招（`Resources/Sprites/UltimateThunder/` 的云、闪电、冲击图）、僵尸焚烧倒地 19 帧（`zombie-boom`）、豌豆/星星命中图（`pea-hit`、`star-hit`） | 效果最好，但数量少 |
| 着色器（`SKShader`） | 雷霆残影溶解 | 只有这一处 |
| 代码粒子发射器（`SKEmitterNode`） | 冰弹尾迹、冰屑、冰晶光环飘点 | 参数在代码里，无法可视化调整 |

### 2.2 相关细节

| 项目 | 现状 | 位置 |
| --- | --- | --- |

| 弹道 | 飞行时间 0.15～0.45 秒；只有冰弹有尾迹 | `Game/AttackStrategy.swift` `ShotAttack.perform` |

## 3. 目标结构

### 3.1 实现方式分工

| 特效类型 | 实现方式 | 适用的现有/新增特效 | 调整方式 |
| --- | --- | --- | --- |
| 粒子类：爆散、尾迹、碎屑、飘落 | Xcode 粒子编辑器 `.sks` + 小贴图 | 墨点、星星、彩纸、烟花火花、雪花、各弹种尾迹、命中碎屑、冰屑 | 在 Xcode 中可视化调参、实时预览 |
| 标志性大特效 | 序列帧（打成纹理图集） | 雷霆大招（已有）、焚烧倒地（已有）；可扩展首领登场、击杀爆点 | 外部工具或素材包出图，替换帧图 |
| 材质效果：闪白、溶解、染色、发光描边 | `SKShader`（每种只编译一次） | 受击闪白、退场溶解、冰冻染色；雷霆残影（已有） | 着色器参数（uniform/attribute） |
| 动作手感：后坐、后仰、弹跳、缓动、震屏 | `SKAction` | 发射后坐、受击后仰、单词卡、飘字、镜头震动 | 代码中的缓动预设 |
| 简单几何：扩散环、光晕、枪口光 | 烘焙贴图 + `SKSpriteNode` | 涟漪、枪口光、命中光圈 | 贴图 + 少量代码参数 |

选择原则：**能用 `.sks` 的不手写粒子；需要高品质且出现次数少的用序列帧；不新增 `SKShapeNode` 一次性特效。**

### 3.2 代码与资源布局

```
Game/FX/
├── FXLibrary.swift    资源加载：.sks 发射器模板、纹理图集、着色器；首用加载并缓存，播放时 copy
├── FXTextures.swift   程序烘焙的小贴图：圆点、柔光晕、星形、环、纸片；白底，运行时着色
├── FXLayer.swift      特效层：挂在 GameScene 下，统一 z 档位、预算、质量档、清理、统计
├── CombatFX.swift     战斗反馈出口：muzzle / trail / impact / hit / defeat，按 ProjectileLook 与皮肤分派
└── FXJuice.swift      手感工具：缓动预设、局部顿帧、镜头震动（仅首领/大招）

Resources/Effects/
├── Particles/         *.sks 粒子文件（ink-burst、sparkle、confetti、firework、snowfall、trail-*、impact-*）
└── Textures/          粒子用小贴图（或由 FXTextures 烘焙，二选一，按观感决定）
```

### 3.3 FXLibrary（资源加载）

- **`.sks` 加载**：`SKEmitterNode(fileNamed:)` 默认只在主程序包中查找，而粒子文件放在 Swift 包资源里，预计需要从 `Bundle.module` 取得文件 URL 后自行解档（见第 6 节，需先验证）。
- **模板 + copy**：每个 `.sks` 只加载一次作为模板，播放时 `copy()` 一份，避免重复解析文件。
- **运行时覆盖**：颜色（`particleColor` 或颜色序列）、数量（`numParticlesToEmit`）、缩放由代码按敌人外观、皮肤和预算覆盖，`.sks` 只定"长什么样"。
- **纹理图集**：序列帧与粒子贴图打成图集，减少纹理切换；现有 `UnitSprites` 的帧缓存继续使用。
- **着色器**：与 `ThunderStrikeEffect.electricShader` 一样静态创建、只编译一次，节点通过 attribute 传入各自进度。

### 3.4 FXTextures（烘焙贴图）

- 沿用 `ThunderStrikeEffect.sparkTextures` 的 CGContext 烘焙方式，辉光画进贴图，不用 `glowWidth`。
- **白色底 + `color` / `colorBlendFactor` 着色**，同一张贴图可以染成不同颜色并保持合批。
- 用于 `.sks` 粒子贴图和简单几何特效；素材全部为经典模式自有，不借用森林地图的 `forest-fx-*`。

### 3.5 FXLayer（特效层）

- 在 `GameScene` 下增加一个特效节点，统一挂载一次性特效；z 档位分为 `trail < impact < burst < overlay`，替代散落的数字。
- **预算**：统计活跃粒子数，超出上限时按比例减少新特效的 `numParticlesToEmit`（参照 `sparkBudget`）。
- **质量档**：普通 / 低（低电量模式或老设备），低档减少粒子、关闭部分尾迹。
- 负责清理：一次性发射器在最长粒子寿命后自删；回合结束可一键清空，便于排查节点堆积。
- 暂停沿用 `scene.speed = 0`；需验证 `SKEmitterNode` 在 `speed = 0` 时是否同样停止（见第 6 节）。

### 3.6 CombatFX（战斗反馈出口）

| 环节 | 现在 | 重构后 |
| --- | --- | --- |
| 发射 | 只有装皮肤才有枪口光（形状节点） | 所有射手都有贴图枪口光；皮肤只覆盖颜色/形状 |
| 飞行 | 冰弹特判 `IceCombatEffects.supports` 才有尾迹 | 每种弹体一份 `.sks` 尾迹（冰晶、星点、叶屑、普通短尾）；冰晶先保持现有实现 |
| 命中 | 冰弹 `impact` 与 `splat` 二选一 | 统一 `impact(projectile:)`：命中帧图 + `.sks` 碎屑，无素材时也有同色小爆点 |
| 受击/击杀 | 受击只闪白；击杀只有粒子 | 受击：闪白着色器 + 轻微后仰；击杀：扩散环 + `.sks` 碎片，两者一眼可分 |

`ShotAttack.perform` 只调用 `CombatFX`，不再内嵌冰弹分支；伤害回调 `onImpact` 的调用时机与次数保持不变。

### 3.7 FXJuice（手感）

- 缓动：统一提供 easeOut 弹出、easeIn 消失等 `SKAction` 组合，替换线性动作。
- 局部顿帧：只让被打中的敌人短暂停住（敌人节点 `speed` 置 0 约 0.04～0.06 秒），**不暂停全场**，避免影响计时与答题节奏。
- 镜头震动：利用现有 `viewCamera`，仅首领登场与大招使用，普通击杀不震。

## 4. 分阶段实施

每个阶段可单独合入、单独验证，按项目规范各自使用独立 worktree 分支。

| 阶段 | 内容 | 改动范围 | 验收 |
| --- | --- | --- | --- |
| 0 基线 | DEBUG 下可开 `showsFPS` / `showsDrawCount` / `showsNodeCount`；在多敌人、多植物、大招三个场面记录帧率、绘制次数、节点数 | `GameScene` 调试开关 | 有可对比的基线数据 |
| 1 `.sks` 试点 | 新建 `FXLibrary`、`Resources/Effects/`；`Package.swift` 增加资源目录；用一个退场效果（如墨点）验证：包内加载、运行时着色、暂停冻结、自动清理 | `Package.swift`、新增 `FX/`、`Effects.swift` 中一个效果 | 真机与 `swift test` 都能加载；暂停时粒子停止；播完无残留 |
| 2 粒子替换 | 其余退场效果、雪花改为 `.sks`；枪口光、涟漪改为烘焙贴图；接口与节点名不变 | `Effects.swift`、`CharacterSkinEffects.shoot`、`FXTextures` | 新增测试：退场效果不含 `SKShapeNode`；绘制次数低于基线；外观经设备确认 |
| 3 特效层 | `FXLayer` 统一挂载、z 档位、预算、质量档、清理 | `GameScene`、各特效挂载点 | 压力场面节点数有上限；暂停时特效冻结；回合结束无残留 |
| 4 战斗反馈 | `CombatFX` 收拢枪口/尾迹/命中；无皮肤射手枪口光；各弹种 `.sks` 尾迹；受击闪白着色器与后仰；击杀分层 | `AttackStrategy.swift`、`DefenderNode.shoot`、`EnemyNode.flash/defeat` | `IceCombatTests`、`CombatAnimationTests`、`UnitSpriteTests` 通过；伤害回调次数不变 |
| 5 手感 | 缓动、局部顿帧、首领/大招震屏 | `FXJuice`、少量调用点 | 连续快速答题时结算正确，节奏不拖慢 |
| 6 序列帧扩展（视美术资源） | 首领登场、击杀爆点等标志性特效改用序列帧图集 | `Resources/Sprites/`、`FXLibrary` | 包体增量在可接受范围；与 `.sks` 碎屑叠加后观感统一 |
| 7 另立需求 | 弹速调整（0.15～0.45 秒上限）、同路齐射 | `fire` 结算等 | 按《战斗视觉反馈优化建议》第 4 节规则边界单独评审 |

建议先做阶段 0～1：阶段 1 是整套分工的前提——先确认 `.sks` 在 Swift 包内能稳定加载、暂停和清理，再批量替换。若 `.sks` 加载方案不可行，退回为"代码配置 `SKEmitterNode` + 烘焙贴图"，后续阶段结构不变。

## 6. 风险与待验证

- **`.sks` 包内加载**：`SKEmitterNode(fileNamed:)` 在 Swift 包资源中能否直接找到文件、需不需要从 `Bundle.module` 手动解档，以及 macOS 测试环境下是否同样可用，阶段 1 先验证。
- **`.sks` 中的贴图引用**：粒子文件按名字引用贴图，贴图不在主程序包时可能加载为空；预计需在加载后由代码重新赋 `particleTexture`。
- **`.sks` 编辑方式**：粒子编辑器需在 Xcode 中打开包内文件使用；需确认在本项目工程结构下能正常预览。
- **发射器生命周期**：`IceCombatEffects.trail` 的注释记录过一次闪退——帧更新中挪动或释放发射器时，渲染层仍引用其粒子。新增发射器沿用同一约束：挂在宿主上随宿主移除，不用 `targetNode`，不在帧更新中改父节点。
- **暂停**：`SKEmitterNode` 在 `scene.speed = 0` 时的行为需实测；若不停止，需在暂停时显式处理 `particleBirthRate` 或发射器 `speed`。
- **序列帧包体**：每个标志性特效的帧数与分辨率需控制，打图集后评估包体增量。
- **观感回归**：替换后颜色、大小可能与现在不同，需在 iPad 上逐个对比确认；现有渲染导出测试可辅助截图对比。
- **性能结论未测**：形状节点开销大是 SpriteKit 的普遍特性，本项目实际收益以阶段 0 基线对比为准。
- **答题节奏**：顿帧、尾迹、命中特效都不得阻塞输入或推迟结算回调。

## 7. 验证方式

- 单元测试：`swift test`（`LearnKit` 包，测试用 `SKRenderer` 真实推进动作），新增"`.sks` 能从包内加载""特效不含 `SKShapeNode`""播完无残留节点""预算上限生效""暂停时粒子停止"等用例。
- 真机：在 iPad 上运行，对比阶段 0 基线的帧率、绘制次数和节点数。
- 每阶段合入前执行 GitNexus `detect_changes`，确认影响范围与预期一致。
